# 风格包契约 v1

## 目的与边界

Red 共享演示行为，允许每个风格拥有不同的视觉语言。风格不是配色；发布会、周报等场景大纲也不等于风格。当前只登记继承的 magazine / swiss，尚未迁入 html-ppt 风格或提取公共运行时源文件。

v1 使用适配清单引用现有模板，避免为增加注册功能移动或重写上游资产。后续共享源提取在独立 PR 中实施；发布模板仍可预先组装，使用者无需构建。

## 文件与字段

每个 `styles/<id>/` 必须有 `style.json`。`node scripts/styles.mjs --check` 自动发现目录并检查引用；没有另一个手工维护的注册列表。

| 字段 | 契约 |
|---|---|
| schemaVersion | 数字 1 |
| id | 与目录名一致的小写英文/数字/连字符标识 |
| name | 用户可读名称 |
| status | experimental 或 stable；新风格先用 experimental |
| runtime | v1 固定 guizang-presenter-v1，表示沿用页面与演讲者契约 |
| template | HTML 模板路径 |
| guide | 此风格的制作入口，明确适用内容和加载顺序 |
| layouts | 登记版式及每种版式的容量、图片槽位 |
| themes | 该风格的配色预设 |
| rules | 额外视觉规则文件列表，可为空 |
| assets | 脚手架须复制的文件列表；均在 assets/ 下，目标保留相同路径 |
| validators | 风格专属 Node .mjs 脚本列表；接收 HTML 绝对路径为首参数，失败返回非零 |

所有资源路径以仓库根目录为基准，不接受绝对路径、父目录跳转或指向仓库外的符号链接。模板与依赖须配合：资源在目标目录的相对引用由包作者维护，脚手架不会推断或重写任意 CSS/JS 内的路径。地图或按需插图的额外依赖由 guide 说明。

`validate-deck.mjs` 总是先运行共用演讲者校验，再运行清单中的风格校验。清单来自受维护的仓库；执行前应像审查代码一样审查新增校验器，不把第三方清单当作无害数据。

## 共用契约与风格边界

- 页面使用唯一、稳定的 `data-slide-id`。备注遵循 `references/presenter-mode.md`，重排不能导致错页。
- 运行时能力沿用 Guizang：翻页、总览、演讲者与观众窗口、低功耗。新增风格不能携带另一套独立键盘/同步运行时。
- 字体、形状、配色、布局、明暗节奏、装饰与动效配方属于风格。Swiss 的 S01–S22 及直角限制只约束 Swiss。
- 溢出、文字可读性、截图保真、页面备注对应关系和可恢复交互是共同验收目标。
- 一个 deck 使用一个风格包。风格不同可能需要重新分配内容与版式，v1 不提供任意整套换肤。

## 新增风格流程

1. 从参考作品提炼规则，记录素材和代码来源。移植第三方代码时保留相应许可声明。
2. 在独立分支新增 experimental 包及实际模板、布局、配色说明；不创建只有名称的空壳风格。
3. 使用共用数据与运行时契约；用现有包作接口参考，不复制其视觉硬规则。
4. 制作包含封面、长中文标题、较密正文、图片、数据或流程、收尾的实际示例，保存截图与测试条件。
5. 校验清单与文件引用、最终页面、演讲者模式和静态模式；记录 CDN/字体/本地文件限制。检查失败时先修复，缺少浏览器验证时保留 experimental。
6. 通过 PR 审查后再升级 stable，并更新 README 的风格目录。

继承的两包标记 stable 代表上游已有风格；当前首批 PR 只验证模板代码未变与静态契约，不构成新的跨浏览器视觉认证。

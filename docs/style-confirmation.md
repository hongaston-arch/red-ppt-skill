# 风格确定与跨聊天确认

## 先判断确认的对象

| 类型 | 需要明确什么 | 决定保存在哪里 |
|---|---|---|
| 新增风格 | 独立设计语言、参考依据、模板、布局与规则 | 新风格 spec.md |
| 修改已有风格 | 基于哪个规格版本，哪些规则改变，影响哪些页面 | 该风格下一规格修订及变更记录 |
| 制作单份 PPT | 风格版本、配色、内容、大纲、素材及本次例外 | 当前 deck 的 PROJECT.md |

“这份封面用照片”只影响当前项目，除非用户明确要求修改风格。涉及“以后都这样”等范围不清的表达时，先澄清适用范围。保持现有风格的常规内容填充、已确认范围内的排版修正不需要新增审批。

## 定义卡的写法

以 [规格模板](templates/style-spec.md) 创建 `styles/<id>/spec.md`，记录：身份与版本、目标与边界、参考来源及具体借鉴点、字体层级、颜色角色、网格与安全区、版式与内容容量、图片处理、动效、禁止项、可调整范围和验收方式。

每条重要规则有稳定 ID、适用范围、依据和状态。区分：

- **来源规则**：能在模板、布局文档或参考页面中查到，不等于用户已经审阅认可。
- **建议**：助手提出的处理方式，尚未成为决定。
- **用户已确认**：有实际明确答复，记录被确认的修订、规则/问题 ID 与范围。
- **待确认**：缺少依据、存在矛盾或仍需用户决定；不自行补齐。

写可检查的行为。例如“截图用 contain，关键文字不可裁切”比“截图漂亮一点”明确。字号、间距、容量等数值必须标明来自现有规范还是待样张验证的候选值。没有依据的事实、案例数据、确认时间和评价不能写成真实信息。

## 两次确认

### 方向确认

先交付定义卡、参考依据、与现有风格的差异及待定问题。只问影响制作的关键点，一次最多 1–3 个。将对指定修订的明确答复记录为方向确认；笼统“可以”只确认紧接着提出的行动或范围，不推导为所有未展示细节都通过。

用户给出完整且明确的视觉要求时，直接整理为定义卡，避免重复提问。现有风格的普通使用不因为新增了 draft 规格文件就必须重新审阅全部规则。

### 样张确认

提供同一内容下的代表页：封面、长中文标题、较密正文、图片、数据或流程、收尾。说明每页使用的版式和待观察问题。示例数据必须标明为测试数据，不能用来支撑现实结论。

用户确认只覆盖所展示修订与页面类型。封面获认可不代表表格页、代码页等未展示结构自动获认可。必要时分批做样张；缺少输入时先完成不依赖该输入的准备，不猜测用户选择。

## 状态分别记录

| 状态 | 表达什么 | 不能据此推导什么 |
|---|---|---|
| 规格草稿 | 已整理可审阅的规则 | 用户已批准 |
| 方向已确认 | 指定范围的设计理解达成一致 | 视觉样张、工程测试通过 |
| 样张已确认 | 指定页面和修订的效果被认可 | 所有版式与浏览器均通过 |
| 工程检查通过 | 指定提交与条件下的检查通过 | 用户视觉认可 |
| 稳定发布 | 经审查后进入稳定发布流程 | 超出实际测试范围的保证 |

`style.json` 的 stable/experimental 是风格包可用状态；与以上确认状态分开。继承风格的 stable 不构成当前用户批准记录。

## 改动与冲突

用户最新明确要求优先执行，但要记录是本次例外还是风格变更；不明确且会改变范围时询问。规则与实现有差异时报告差异，不把代码当作已确认的新决定。参考图片与文字要求矛盾时指出冲突。

规格修订变化时重新检查受影响项，不重复要求确认未变部分。改变字体体系、颜色角色、主要网格、版式骨架、截图裁切策略或动效语言应展示受影响样张；纠正错字、修复溢出或按已确认规则调整间距可继续执行。

确认记录包含：规格修订、规则/问题 ID、用户原意的准确摘要、范围及关联样张。能确认日期时可写日期，不能补造缺失的历史信息。没有实际答复时保持待定，时间经过不代表同意。

## 跨聊天恢复

维护助手通过根目录 `AGENTS.md` → `CONTEXT.md` → 涉及的风格规格恢复。单份 PPT 使用 [PROJECT 模板](templates/deck-project.md) 记录内容与选择；项目内有规格快照时先核对其修订与当前仓库的差异，再决定沿用还是迁移，不静默替换。

风格包可在 `style.json` 中登记 `spec` 和 `specRevision`。脚手架会把规格复制到新 deck 的 `style-spec.md`，并记录内容摘要，保证来源可以核对。快照只记录创作依据，不把草稿变成确认。PROJECT.md 另行记录实际选择与用户答复，不能由脚手架虚构。

新聊天简短复述当前目标、实际版本、已确认范围和下一步后继续；文件缺失、分支不符或互相冲突时说明具体差异。不能保证未打开仓库、未读取文件的聊天自动继承历史。
